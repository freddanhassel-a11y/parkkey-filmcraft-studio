# ParkKey Film Studio

Create a new standalone full-stack project named “ParkKey™ Film Studio”. This project is ONLY for producing, planning, managing and exporting ParkKey™ advertising films and campaign videos.

MANDATORY: use the existing workspace skills as governing instructions for every relevant task, especially: `parkkey-master`, `parkkey-video`, `parkkey-brand-theme`, `parkkey-visual-content`, `parkkey-design-system`, `parkkey-truth-proof`, `parkkey-accessibility-release-qa`, and where relevant `parkkey-ai-governance`, `parkkey-security-privacy`, `parkkey-commercial-comms`. Do not invent a competing style system. Treat these skills as canonical.

VISUAL DIRECTION
Build a cinematic premium ParkKey interface, not a generic SaaS dashboard. Follow ParkKey brand: Forest Green #0F3D2E, Park Green #8CC63E, Pale Cream #F5F5EB, Graphite #1E1E1E, Montserrat, premium midnight/navy extensions, restrained gold warmth, transparent glass only where readable. The atmosphere should feel Nordic, cinematic, premium, human and agency-grade. Parky™ is a guide/reward character, not a decorative sticker. Every visible surface should feel recognizably ParkKey.

CORE PRODUCT AREAS
1. Dashboard: latest films, projects in progress, recent exports, favorites, prompt templates and a dominant “Create new film” CTA.
2. Film Creator: campaign goal, audience, duration, target format, channel, CTA, visual mood, location/time, Parky usage, device/product interaction, music direction, voice/subtitle/SFX toggles, reference media, notes.
3. Prompt Engine: automatically combine user brief + ParkKey workspace skills into a complete master prompt, storyboard, scene-by-scene shot list, continuity bible, music brief, motion/editing brief, UI/text rules, negative prompts and export specification. Allow one-click copy/download of prompts.
4. Film Library: cards with poster/thumbnail, title, campaign, duration, aspect ratio, version, date, status, tags, notes and export/download actions. Search/filter by campaign, format, status and tag.
5. Asset Library: ParkKey logos, Parky canonical references, campaign key art, image/video references, music references/briefs, CTA variants and brand assets. Support upload and classification.
6. Prompt Library: reusable templates for Parky Test, Municipality, Mobility Operator, Local Commerce, Investor/Brand, Event/Launch, Existing App demo.
7. Versioning: V1/V2/V3 etc, changelog/notes, duplicate version, compare metadata.
8. Export presets: 16:9 1920x1080, 9:16 1080x1920, 1:1, 4:5; durations 6/15/30/35/60 sec; 30fps default; H.264 MP4 master when supported.
9. QA gate before export: correct ParkKey logo, canonical Parky, readable/real UI, no pseudo-text, no invented partner logos, no generative character drift, no slideshow/pan-zoom feel, no synthetic tech plinks when disabled, CTA correct, voice/subtitle/SFX toggles respected, safe areas, aspect ratio, 30fps/H.264, evidence/demo labels when needed.
10. Download/export: completed videos uploaded or generated by integrations must have a real downloadable MP4 action. Do not fake download buttons. If no rendered asset exists, show a truthful “No rendered file yet” state with next action.
11. Integration area: provider-agnostic architecture for future Firefly/video-generation APIs. Build the app so prompt generation/library works now even if no external video API is connected. Add integration status and clean adapter boundary rather than hard-coding one provider.
12. Settings / Skills panel: visibly show which ParkKey skills are active for this studio and what each governs. Every new film project must automatically inherit the ParkKey rules.

DATA MODEL
Use a scalable model for film_projects, film_versions, prompts, prompt_templates, assets, renders/exports, tags and QA_checklists. Use Lovable Cloud/Supabase if appropriate. Preserve truthful statuses: DRAFT, PROMPT READY, RENDERING, READY FOR QA, APPROVED, EXPORTED; do not show fake progress.

FIRST BUILT-IN FILM PROJECT
Pre-create a project called “Parky-testet — AAA/Guldägget master”. The visual reference is the supplied Parky-test storyboard from this conversation: sunny Nordic autumn city, ParkKey/Parky premium cinematic look. The film brief is:
- 30–35 seconds
- 1920x1080, 30fps, H.264 MP4 target
- main character completes Parky-testet on a MOBILE PHONE in a sunny Nordic autumn city
- canonical Parky appears as an animated AI assistant and guides visually
- no voiceover, no subtitles, no sound effects
- warm real premium advertising music: acoustic piano, muted/nylon guitar, soft live-feel drums/percussion, warm bass, very sparse strings/pad
- absolutely no drone, synth-plink, tech chime, digital beeps or synthetic corporate music
- music must have a memorable melodic hook/jingle and scene changes cut on musical beats
- true motion/live-action feel: longer tracking/dolly/gimbal camera moves, person walking, looking, tapping/scrolling test, natural hand movement
- Parky reacts with blinking, eye-line, body motion and hand gestures, not a static sticker
- autumn leaves, public transit, cyclists, pedestrians and cafés move naturally in background
- premium transitions motivated by movement/light/foreground wipes; avoid slideshow, Ken Burns, simple pan/zoom
- show actual interaction journey rather than explanatory text cards
- final clean branded end frame focused on correct ParkKey logo and ParkKey.org/test CTA
- preserve the storyboard’s visual mood and scene logic, but make the final film more dynamic and mobile-first.

For this first project, automatically generate and save:
A) master production prompt,
B) scene-by-scene storyboard (approx 7–9 scenes),
C) shot list with duration/camera/action/Parky/UI/music cue/transition,
D) continuity bible,
E) music brief with hook structure and beat map,
F) negative prompt / avoid list,
G) export + QA checklist.

QUALITY
No dead buttons. Responsive desktop/mobile/tablet. Accessible keyboard/focus. Truthful empty/error/loading states. Run build/type checks and test the core flow: create project → generate prompt → save → library → open version → QA → export/download state. Do not publish externally yet unless explicitly asked.
